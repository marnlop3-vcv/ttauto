# ระบบจัดตารางสอนอัตโนมัติ

เว็บแอป (React + Vite + TypeScript) สำหรับจัดตารางสอนอัตโนมัติ ข้อมูลเก็บในเบราว์เซอร์ (localStorage) ไม่ต้องมีเซิร์ฟเวอร์ฐานข้อมูล

## วิธีติดตั้งและใช้งาน
ต้องมี Node.js 18 ขึ้นไป

```bash
npm install          # ติดตั้ง
npm run dev          # รันโหมดพัฒนา  -> http://localhost:5173
npm run build        # สร้างไฟล์สำหรับใช้งานจริงในโฟลเดอร์ dist/
npm run preview      # เปิดดูผล build  -> http://localhost:4173
npm test             # ทดสอบตัวแปลงเงื่อนไขภาษาไทยและอัลกอริทึมจัดตาราง
```
โฟลเดอร์ `dist/` นำไปวางบน web server ใดก็ได้ (เช่น Nginx, GitHub Pages, โฮสต์ของโรงเรียน) — ใช้ hash routing จึงไม่ต้องตั้งค่า rewrite
(ห้ามดับเบิลคลิกเปิด `index.html` ตรงๆ เพราะเบราว์เซอร์บล็อกสคริปต์แบบ module จาก file://)

## ขั้นตอนการใช้งาน
1. **กรอกข้อมูล › ตั้งค่าคาบเรียน** — เลือกวันที่เปิดสอน, จำนวนคาบต่อวัน, เวลาแต่ละคาบ, พักเที่ยงหลังคาบที่เท่าไร (ต้องตั้งก่อน)
2. กรอก **ครู / กลุ่มเรียน / วิชาเรียน / ห้องเรียน (อาคาร)** — กรอกทีละรายการ หรือกด *ดาวน์โหลด Template Excel* → กรอก → *Import จาก Excel* (ระบบตรวจแถวที่ผิด/ซ้ำและรายงานให้)
3. **กรณีพิเศษ** — พิมพ์เงื่อนไขเป็นภาษาไทย ระบบแสดงผลที่แปลงได้ให้ตรวจก่อนบันทึก
4. **กำหนดการเรียน** — เลือก วิชา + ครูสอนหลัก/สอนร่วม (หลายคนได้) + กลุ่มเรียน (หลายกลุ่มได้) + ห้อง แล้วกด *บันทึก*
5. ไปที่ **Dashboard** กด *จัดตารางอัตโนมัติ* → เลือกดูตามครู/กลุ่มเรียน/อาคาร → *Export PDF / Excel*

ปุ่ม **ข้อมูลตัวอย่าง (เล็ก / กลาง / ใหญ่)** ในหน้า กรอกข้อมูล โหลดข้อมูลครบชุดทันที (4 / 12 / 30 กลุ่มเรียน) ส่วน `sample-data/small|medium|large/` มีไฟล์ Excel / CSV / JSON ของทุกแท็บสำหรับทดลอง Import และ `dataset.json` (ชุดสมบูรณ์รวมกำหนดการเรียน ใช้ปุ่ม "กู้คืนข้อมูล")

## รูปแบบเงื่อนไขกรณีพิเศษที่รองรับ
| พิมพ์ | ความหมาย |
|---|---|
| `ทุกวันคาบที่ 1` | ทุกวันที่เปิดสอน คาบ 1 |
| `วันพุธ คาบ 7-8` | พุธ คาบ 7 และ 8 |
| `จันทร์-ศุกร์ คาบสุดท้าย` | จันทร์ถึงศุกร์ คาบสุดท้ายของวัน |
| `วันศุกร์ ช่วงบ่าย` / `ช่วงเช้า` | ตามคาบพักเที่ยงที่ตั้งไว้ |
| `คาบที่ 2,4` / `คาบ 1 และ 3` | หลายคาบ |
| `จันทร์ คาบ 1; พุธ คาบ 3` | หลายเงื่อนไข คั่นด้วย `;` หรือขึ้นบรรทัดใหม่ |

เลขไทยและการเว้นวรรคใช้ได้ "จำนวนคาบ" = จำนวนคาบต่อเนื่องต่อครั้ง ถ้าเงื่อนไขระบุคาบเริ่มต้นคาบเดียว (เช่น `วันพุธ คาบ 7` + จำนวนคาบ 2 = คาบ 7–8)
กรณีพิเศษมีผลกับ **ทุกกลุ่มเรียนและทุกครู** เว้นแต่เลือกกลุ่มเรียนเฉพาะ

## Import ไฟล์ Excel / CSV / JSON
ทุกแท็บ (ครู, กลุ่มเรียน, วิชา, อาคาร, กรณีพิเศษ) นำเข้าได้จาก `.xlsx`, `.csv`, `.json` ผ่านกฎตรวจสอบเดียวกับฟอร์ม (ซ้ำ/ค่าว่าง/ตัวเลขผิดจะถูกข้ามและรายงานเลขแถว) กด Template เพื่อดาวน์โหลดหัวตารางในรูปแบบที่ต้องการ
- **จับคู่คอลัมน์ตามชื่อหัวตาราง** (ลำดับสลับได้ มีคอลัมน์เกินได้) รองรับชื่อภาษาไทยตาม Template และชื่ออังกฤษ (`name`, `role`, `code`, `major`, `periodsPerWeek`, `floors`, `roomsPerFloor`, `condition`, `groups`, `teachers` …)
- **CSV:** UTF-8 (มี/ไม่มี BOM), UTF-16, หรือ Windows-874 (ตรวจอัตโนมัติ); ตัวคั่น `,` `;` Tab; มีเครื่องหมายคำพูด/ขึ้นบรรทัดใหม่ในช่องได้
- **JSON:** อาร์เรย์ของอ็อบเจ็กต์, อาร์เรย์ของอาร์เรย์, หรือ `{ "teachers": [...] }` (คีย์ที่ขึ้นต้นด้วย `_` ถูกข้าม) ดึงเฉพาะคีย์ที่รู้จัก
- **ข้อจำกัด:** ไฟล์ ≤ 5 MB, ≤ 20,000 แถว; `.xlsx` อ่านชีตแรก; ไม่รองรับ `.xls` เก่า; ทุกค่าอ่านเป็นข้อความ (รหัสเช่น `06701` ไม่เสียเลข 0); Import ครู/กลุ่มเรียนก่อนกรณีพิเศษ
- ข้อมูลประมวลผลในเบราว์เซอร์ ไม่อัปโหลดไปที่ใด

## อัลกอริทึมจัดตาราง
1. **กรณีพิเศษ** ล็อกช่องเวลาก่อน (ทุกคน หรือเฉพาะกลุ่ม/ครู)
2. **Greedy:** วางทีละ "ชิ้น" (ทุกวิชาแบ่งเป็นช่วงติดกัน ช่วงละ ≤4 คาบ เช่น 5 = 3+2) เรียงจากยากก่อน เลือกตำแหน่งที่ทำให้คะแนนความไม่สวยเพิ่มน้อยที่สุด
3. **ซ่อมแซม (Ejection chain + Tabu):** ชิ้นที่วางไม่ลง จะย้ายชิ้นที่ขวางไปที่อื่นเป็นทอดๆ
4. **Simulated Annealing:** ย้าย/สลับชิ้นไปเรื่อยๆ โดยไม่ละเมิดข้อบังคับ (ครู/กลุ่ม/ห้องห้ามชน, กรณีพิเศษ) ยอมรับการเปลี่ยนที่แย่ลงเล็กน้อยในช่วงแรก แล้วเข้มงวดขึ้นตามเวลา เก็บคำตอบที่ดีที่สุดไว้
5. **คะแนนความไม่สวย** = คาบว่างคั่นของนักเรียน/ครู, ครูสอนติดกันเกิน 4 คาบ, ภาระรายวันไม่สมดุล, วิชากระจุกวันเดียว (ปรับน้ำหนักได้ที่ `WEIGHTS` ใน `src/lib/scheduler.ts`)

หมายเหตุ: ไม่รับประกันคำตอบที่ดีที่สุด แต่ข้อบังคับไม่ถูกละเมิดแน่นอน ถ้าข้อมูลขัดแย้งกันจริง (เช่น ครูสอนเกินจำนวนช่องที่มี) ระบบจะรายงานวิชาที่จัดไม่ได้พร้อมสาเหตุ
ทดสอบความเร็ว: `BENCH=1 npx vitest run tests/bench.test.ts`

## ระบบรหัสผ่านและมุมมอง (นักเรียน / ครู / ผู้ดูแล)
เว็บเป็น static ไม่มีเซิร์ฟเวอร์ จึงไม่มี "บัญชีผู้ใช้" แต่ใช้ **ไฟล์ตารางที่เข้ารหัส**:
1. ผู้ดูแลจัดตารางตามปกติ แล้วไปเมนู **เผยแพร่ตาราง** ตั้งรหัสนักเรียนและรหัสครู (กด "สร้างรหัสให้") → ดาวน์โหลด `published.enc.json`
2. วางไฟล์ที่ `public/published/published.enc.json` (ทับไฟล์เปล่าเดิม) แล้ว push → GitHub Actions เผยแพร่ (หรือส่งไฟล์ให้ผู้ดูทางไลน์ แล้วให้เลือกไฟล์ที่หน้าเข้าสู่ระบบ)
3. ผู้ดู เปิดเว็บ ใส่รหัสช่องเดียว ระบบลองถอดรหัสทีละซอง ซองไหนถอดได้ = มุมมองนั้น
   - **นักเรียน:** ตารางรายกลุ่มเรียน เลือกห้องได้ Export ได้ แก้ไขไม่ได้
   - **ครู:** ตารางรายครู เลือกครูได้ Export ได้ แก้ไขไม่ได้
   - **ผู้ดูแล:** แอปเดิมทั้งหมด (ตั้งรหัสล็อกเฉพาะเครื่องได้ที่เมนู เผยแพร่ตาราง; ไม่ตั้งก็เข้าได้ด้วยปุ่ม "ใช้งานเป็นผู้ดูแล")
- **ความปลอดภัยมาจากการเข้ารหัสจริง** (PBKDF2-SHA256 600,000 รอบ → AES-256-GCM, WebCrypto) ไม่ใช่การซ่อนปุ่ม: ซองนักเรียนมีเฉพาะตารางรายกลุ่มที่คำนวณเสร็จ (ไม่มีกำหนดการเรียน/รายชื่อครูทั้งหมด) รหัสนักเรียนถอดซองครูไม่ได้ รหัสผิดหรือไฟล์ถูกแก้ถอดไม่ได้
- **ข้อจำกัด:** ไฟล์เปิดสาธารณะ จึงถูกเดารหัสแบบออฟไลน์ได้ → ระบบบังคับรหัส ≥ 10 ตัวและเดายาก; รหัสเป็นรหัสร่วม ยกเลิกสิทธิ์รายคนไม่ได้ (รหัสหลุด = เปลี่ยนรหัสแล้วเผยแพร่ใหม่ แต่ไฟล์เก่าในประวัติ git ยังถอดด้วยรหัสเก่าได้); ระบบไม่เก็บรหัส; ตารางอัปเดตเมื่อเผยแพร่ใหม่เท่านั้น; รหัสล็อกผู้ดูแลเป็นเพียงการล็อกหน้าจอ ไม่ได้เข้ารหัสข้อมูลในเครื่อง
- ถ้าต้องการรหัสรายบุคคล/ยกเลิกสิทธิ์รายคน/ซิงก์เรียลไทม์ ต้องมีระบบหลังบ้านจริง (เช่น Supabase/Firebase)
- โค้ด: `src/auth/` (`crypto.ts`, `bundle.ts`, `session.ts`, `adminLock.ts`), `src/pages/Login.tsx`, `Viewer.tsx`, `Publish.tsx` • ทดสอบ: `tests/auth.test.ts`, `node scripts/e2e-auth.cjs`

## เผยแพร่บน GitHub Pages (สาธารณะ ฟรี)
1. สร้างรีโพ **public** บน GitHub (ชื่อรีโพจะอยู่ในลิงก์ `https://<ชื่อบัญชี>.github.io/<ชื่อรีโพ>/`)
2. ใช้อีเมล noreply ของ GitHub ตอน commit (Settings › Emails › Keep my email private) แล้วตั้ง `git config user.name` / `user.email`
3. แก้ชื่อผู้พัฒนาในไฟล์ `LICENSE` (บรรทัด Copyright)
4. push โค้ดขึ้นสาขา `main`:
   ```
   git init -b main
   git add .
   git commit -m "Initial release"
   git remote add origin https://github.com/<ชื่อบัญชี>/<ชื่อรีโพ>.git
   git push -u origin main
   ```
5. GitHub › Settings › Pages › Build and deployment › Source = **GitHub Actions** (ตั้งครั้งเดียว)
6. ดูผลที่แท็บ Actions เมื่อเขียวแล้ว เว็บจะขึ้นที่ลิงก์ข้างบน (ครั้งต่อไปแค่ push ก็อัปเดตเอง)
- `vite.config.ts` ตั้ง `base: './'` และใช้ hash routing จึงวางที่ซับโฟลเดอร์ได้โดยไม่ต้องแก้ ตรวจได้ด้วย `npm run build && node scripts/smoke-subpath.cjs`
- ข้อมูลผู้ใช้อยู่ในเบราว์เซอร์ของผู้ใช้แต่ละคน (localStorage) ไม่มีที่เก็บกลาง จึงไม่ปนกัน และเจ้าของเว็บมองไม่เห็นข้อมูลของผู้ใช้
- ถ้าเปลี่ยนที่อยู่เว็บ ผู้ใช้เดิมจะไม่เห็นข้อมูลเดิม (localStorage แยกตามที่อยู่) — ให้ผู้ใช้สำรอง/กู้คืนไฟล์ JSON
- ซอฟต์แวร์ที่ใช้ดู `THIRD_PARTY_NOTICES.md`

## ข้อสมมติที่ควรทราบ
- **จำนวนห้อง = ห้องต่อชั้น** ห้องตั้งชื่อเป็น `ชั้น + เลข 2 หลัก` เช่น ชั้น 2 ห้อง 3 = `203`
- ตารางแสดงอาคาร + รหัสห้อง ทุกมุมมอง (ตารางอาคารแสดงรหัสห้องในวงเล็บหลังชื่อวิชา)
- ครูสอนหลัก/สอนร่วม ถูกกรองตาม "หน้าที่" ที่กำหนดไว้ในหน้าครู
- การลบข้อมูลที่ถูกใช้ในกำหนดการเรียน จะแก้/ลบกำหนดการที่เกี่ยวข้อง และล้างตารางที่จัดไว้ (มีข้อความยืนยันก่อน)
- ข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้น — ใช้ปุ่ม "สำรองข้อมูล (JSON)" เพื่อย้ายเครื่อง/กันข้อมูลหาย
