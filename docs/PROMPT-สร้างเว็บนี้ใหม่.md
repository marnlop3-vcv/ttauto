# Prompt สำหรับให้ Claude สร้าง "ระบบจัดตารางสอนอัตโนมัติ" ขึ้นมาใหม่ (ให้ได้เหมือนเวอร์ชัน 1.8.0)

## อ่านก่อน (สั้นๆ)

- **ผลจะ "ใกล้เคียงมาก" แต่ไม่เหมือนทุกบรรทัด** เพราะ AI เขียนโค้ดใหม่ทุกครั้ง ถ้าต้องการ **เหมือนเป๊ะ** ให้ clone รีโพ `marnlop3-vcv/ttauto` มาแล้วทำต่อ ไม่ต้องเขียนใหม่
- **วิธีใช้ที่ได้ผลดีที่สุด:** ส่ง prompt เป็น **ขั้นๆ ตามหัวข้อ B** (ทีละเฟส ตรวจแล้วค่อยไปต่อ) ดีกว่ายัดทั้งหมดในข้อความเดียว หรือถ้าจะส่งทีเดียว ใช้ **หัวข้อ A** และเปิดโหมดวางแผน (Plan mode) ให้ Claude วางแผนก่อน
- เริ่มเซสชันใหม่ที่ผูกกับ **รีโพเปล่าที่สร้างไว้แล้ว** (ดูวิธีตั้งค่าในคำตอบก่อนหน้า) และให้ Claude ติดตั้ง Playwright/ทดสอบได้
- แนบไฟล์ `docs/CODE-GUIDE.md` ให้ Claude อ่านเป็น "แผนที่" ได้ด้วย ถ้าอยากให้โครงสร้างไฟล์ตรงกัน

## 2) ข้อมูลที่ผู้ใช้กรอก (โมเดลข้อมูล)
- การตั้งค่า: วันที่เปิดสอน (จันทร์–อาทิตย์เลือกได้), จำนวนคาบต่อวัน (1–14) พร้อมเวลาเริ่ม–จบของทุกคาบ (ตรวจไม่ให้ทับซ้อน), "พักเที่ยงหลังคาบที่ k" (หรือไม่มีพัก) เปลี่ยนค่านี้หลังจัดตารางแล้วต้องถามยืนยันและล้างตาราง
- ครู: ชื่อ + หน้าที่ (ครูสอนหลัก/ครูสอนร่วม) **ครูชื่อเดียวกันแต่คนละหน้าที่เพิ่มได้ และถือเป็นคนเดียวกัน (ไม่ให้สอนชนกัน)** ชื่อเดียวกัน+หน้าที่เดียวกันห้ามซ้ำ
- กลุ่มเรียน: รหัส, ชื่อ, สาขาวิชา
- วิชา: รหัส, ชื่อ, จำนวนคาบต่อสัปดาห์
- อาคาร: ชื่อ, จำนวนชั้น, จำนวนห้องต่อชั้น (ระบบสร้างเลขห้องเอง ชั้น 2 ห้อง 3 = ห้อง 203)
- กรณีพิเศษ: ชื่อ, จำนวนคาบ, เงื่อนไข (พิมพ์ภาษาไทย), กลุ่มเรียนที่เกี่ยวข้อง และ/หรือครูที่เกี่ยวข้อง (เลือกหลายรายการได้; ไม่เลือกเลย = ใช้กับทุกกลุ่มและทุกครู) ตัวแปลเงื่อนไขรองรับ: "ทุกวันคาบที่ 1", "วันพุธ คาบ 7-8", "จันทร์-ศุกร์ คาบสุดท้าย/คาบแรก", "วันศุกร์ ช่วงบ่าย/ช่วงเช้า" (ต้องมีพักเที่ยง), หลายเงื่อนไขคั่นด้วย ";" หรือขึ้นบรรทัดใหม่, เลขไทย/ช่องว่างได้, ถ้าระบุคาบเริ่มเดียวและจำนวนคาบ >1 ให้วางต่อเนื่อง แสดงแถบ "ระบบเข้าใจว่า: …" ก่อนกดเพิ่ม และแจ้ง error ที่อ่านรู้เรื่องพร้อมตัวอย่าง
- กำหนดการเรียน (Assignment): วิชา 1 วิชา + ครูสอนหลัก (หลายคน) + ครูสอนร่วม (ไม่บังคับ) + กลุ่มเรียน (หลายกลุ่ม) + **ห้อง (เลือกได้หลายห้อง/หลายอาคารพร้อมกัน สำหรับ "วิชาเสรี": ปุ่ม "＋ เพิ่มห้อง" แสดงเป็นชิป ลบได้ เก็บเป็น `room` (ห้องหลัก) + `extraRooms?` (ไม่บังคับ ข้อมูลเก่าใช้ได้ ไม่ต้อง migrate); ทุกห้องถูกจองพร้อมกัน)** + ตัวเลือก "เรียนรวมกัน / แยกเรียน"
- ทุกช่องเลือกต้องพิมพ์ค้นหาได้ (SearchSelect/SearchMulti) ปุ่มลบรายการ (ไม่มีปุ่มแก้ไข) ลบข้อมูลที่ถูกใช้อยู่ต้องเตือน และจัดการกำหนดการเรียนที่เกี่ยวข้องให้ (ลบอาคาร: ตัดเฉพาะห้องของอาคารนั้น ถ้ายังเหลือห้องอื่นให้คงกำหนดการไว้)
- นำเข้า/ส่งออก: ทุกชนิดมี Template ดาวน์โหลดเป็น Excel/CSV/JSON (มีหัวตารางภาษาไทย+ตัวอย่าง+หมายเหตุ) และ Import จากไฟล์ .xlsx/.csv/.json (ไม่เกิน 5 MB; ตรวจทีละแถวด้วยกฎเดียวกับฟอร์ม; แถวผิดข้ามพร้อมแจ้งเลขแถวและเหตุผล แถวถูกนำเข้า; รายการซ้ำไม่เพิ่มซ้อน; รองรับหัวคอลัมน์ภาษาอังกฤษ/ไทย; CSV UTF-8) หัวคอลัมน์: ครู(ชื่อครู, หน้าที่) กลุ่ม(รหัสกลุ่มเรียน, ชื่อกลุ่มเรียน, สาขาวิชา) วิชา(รหัสวิชา, ชื่อวิชา, จำนวนคาบต่อสัปดาห์) อาคาร(ชื่ออาคาร, จำนวนชั้น, จำนวนห้อง (ต่อชั้น)) กรณีพิเศษ(ชื่อ, จำนวนคาบ, เงื่อนไข, รหัสกลุ่ม, ชื่อครู)
- เครื่องมือ: สำรองข้อมูล (JSON) / กู้คืน / ล้างข้อมูลทั้งหมด (ถามยืนยัน) / โหลดข้อมูลตัวอย่าง 3 ขนาด เล็ก 4 กลุ่ม 64 คาบ, กลาง 12 กลุ่ม 264 คาบ, ใหญ่ 30 กลุ่ม 720 คาบ (สร้างแบบกำหนดแน่นอน ไม่สุ่ม ออกแบบให้จัดได้ครบ มีครูชื่อซ้ำคนละหน้าที่ กรณีพิเศษ 3 รายการ และกลุ่มที่เรียนรวมกัน) พร้อมโฟลเดอร์ sample-data/ ที่มีไฟล์ Template ตัวอย่างทั้ง 3 ขนาดและ README.txt

## 3) ตัวจัดตาราง (หัวใจ) — ใน Web Worker (หน้าจอไม่ค้าง มีแถบความคืบหน้า ปุ่มหยุด) พร้อมทางสำรองถ้า Worker ใช้ไม่ได้
อัลกอริทึม 3 ขั้นต่อกัน ข้อบังคับ (ครู/กลุ่มเรียน/ห้องไม่ชน และช่องที่ล็อกจากกรณีพิเศษ) ห้ามถูกละเมิดตลอดเวลา:
0. เตรียมข้อมูล: ครูระบุตัวตนด้วย "ชื่อ"; กรณีพิเศษ "ล็อกช่อง" ของทรัพยากรที่เกี่ยวข้องก่อน (ไม่ระบุกลุ่ม/ครู = ล็อกทุกอย่าง); กำหนดการ "เรียนรวมกัน" ที่ วิชา+ครู+ชุดห้อง เดียวกันรวมเป็น Unit เดียว (ต้องว่างพร้อมกันทุกกลุ่ม), "แยกเรียน" แตกเป็น Unit ละกลุ่ม; ทรัพยากรของ Unit = ครู + กลุ่มเรียน + ทุกห้อง
   **แบ่งวิชาเป็นช่วงติดกัน (Piece) ช่วงละไม่เกิน 4 คาบ ไม่คร่อมพักเที่ยง ใช้จำนวนช่วงน้อยสุดและแบ่งเท่าๆ กัน: 1–4 คาบ = ช่วงเดียว, 5=3+2, 6=3+3, 7=4+3, 8=4+4, 9=3+3+3, 10=4+3+3** (ถ้าครึ่งวันสั้นกว่านี้ ให้แบ่งให้พอดีครึ่งวันและแจ้งเตือน) ช่วงของวิชาเดียวกันพยายามอยู่คนละวัน
1. Greedy: เรียงชิ้นยากก่อน (ขนาด × จำนวนทรัพยากร + สุ่มเล็กน้อย) วางตำแหน่งที่ไม่ชนและทำให้คะแนนความไม่สวยเพิ่มน้อยสุด
2. ซ่อมด้วย Ejection Chain + Tabu: ชิ้นที่วางไม่ลง → เลือกตำแหน่งที่มีชิ้นขวางน้อยสุด (ตำแหน่งติดช่องล็อกใช้ไม่ได้) → ไล่ชิ้นขวางเข้าคิวแล้ววาง; Tabu ห้ามไล่ชิ้นเดิมซ้ำ 8–15 รอบ (ซ่อมหลัง Greedy: 400+40×ชิ้นค้าง รอบ ไม่เกิน 3 วินาที)
3. Simulated Annealing: สุ่มชิ้น → ย้ายไปตำแหน่งสุ่ม 45% / เลื่อน ±1–3 คาบ 30% / สลับกับชิ้นขนาดเท่ากัน 25%; รับเมื่อดีขึ้นหรือแย่ลงด้วยความน่าจะเป็น e^(−Δ/T) (Metropolis); T = 2.0×(0.03/2.0)^(เวลาที่ใช้/เวลาที่ตั้ง) คำนวณคะแนนแบบเฉพาะส่วน (incremental); เก็บคำตอบดีที่สุดไว้ตลอด; ทุก 6,000 รอบถ้ายังมีชิ้นค้างให้เรียกซ่อมซ้ำ; ถึง 50% ของเวลาถ้าวิชาที่ต้องติดกันยังวางไม่ลง ให้แยกเป็นช่วงย่อยและแจ้งเตือน; จบก่อนเวลาเมื่อ ≥45% ของเวลา+วางครบ+ไม่ดีขึ้นเกิน max(1.5 วินาที, 40% ของเวลา); ตัวสุ่มกำหนด seed ได้ (mulberry32); เวลาสูงสุดเริ่มต้น 15 วินาที (เลือก 5/15/30/60/120)
- คะแนนความไม่สวย (WEIGHTS): คาบว่างคั่นของกลุ่มเรียน 8/คาบ, ของครู 2/คาบ, ครูสอนติดเกิน 4 คาบ 3/คาบ (พักเที่ยงตัดช่วง), ภาระรายวันไม่สมดุล 0.4 (กลุ่ม) 0.15 (ครู) × กำลังสอง, ช่วงของวิชาเดียวกันอยู่วันเดียวกัน 2/คู่, ช่วงวิชาเดียวกันวางชิดกันจนยาวเกิน 4 คาบ 40/รอยต่อ (ไม่นับคร่อมพักเที่ยง), ชอบคาบต้นๆ 0.03
- ผลลัพธ์: รายการคาบ, กรณีพิเศษที่วางแล้ว, รายการที่จัดไม่ได้พร้อม **สาเหตุอ่านรู้เรื่อง** (เช่น ครูมีคาบว่างไม่พอ), คำเตือน, จำนวนที่รวมเรียนพร้อมกัน, ตัวชี้วัด ก่อน→หลังปรับ (คาบว่างคั่นนักเรียน/ครู, ครูสอนติดเกิน 4)

## 4) หน้าจอสำหรับผู้ดูแล (เมนูซ้าย: Dashboard / กรอกข้อมูล / เผยแพร่ตาราง / วิธีใช้)
- Dashboard: ปุ่มสลับมุมมอง ครู / กลุ่มเรียน / อาคาร + ช่องเลือกที่ค้นหาได้; ตารางวัน × คาบ ชนิดที่ช่องสอนติดกันรวมเป็นช่องเดียวพร้อมป้าย "N คาบติดกัน", คั่นพักเที่ยง, **เรียนรวมหลายกลุ่มรวมเป็นรายการเดียวในมุมมองครู/อาคาร**, กรณีพิเศษสีต่างจากวิชา, ใต้ตารางมีสรุปจำนวนคาบต่อสัปดาห์ (ต่อวิชา/ห้อง) แยกกรณีพิเศษ; มุมมองหลายห้อง (วิชาเสรี): กลุ่ม/ครูเห็นทุกอาคารในช่องเดียว ("อาคาร 1 ห้อง 101 • อาคาร 2 ห้อง 203"), มุมมองอาคารเห็นเฉพาะห้องของอาคารนั้น + ข้อความ "ใช้พร้อมกับ …"
- Export PDF (ตารางที่แสดง), Export Excel (รายการเดียว/ทุกรายการ แยกชีต เซลล์ที่ติดกันถูกรวมเซลล์), แสดงแถบสถานะ (วางแล้ว X/Y คาบ, รวมสอนพร้อมกัน, คาบว่างคั่น ก่อน→หลัง, เวลาที่จัด), กล่องแดงสาเหตุที่จัดไม่ได้, กล่องเหลืองคำเตือน, ข้อความ "ข้อมูลเปลี่ยนหลังจัดตาราง กดจัดใหม่" เมื่อ stale
- ตัวนำทาง "เริ่มต้นใช้งาน" (การ์ดบน Dashboard): 4 ขั้นบังคับ (ตั้งค่าคาบ → เพิ่มข้อมูล ครู/กลุ่ม/วิชา/ห้อง (ติ๊กย่อย) → กำหนดการเรียน → จัดตาราง) + ขั้นเผยแพร่ (ไม่บังคับ) ติ๊กถูกอัตโนมัติ (ฟังก์ชันบริสุทธิ์ guideSteps ทดสอบได้), ปุ่มลัดไปแท็บที่ถูกต้องผ่าน `#/input?tab=…`, ปุ่ม "✨ ลองใช้ด้วยข้อมูลตัวอย่าง" (เมื่อยังว่าง), ย่อ/ขยายและจำค่า, ครบแล้วเป็นแถบ "ทุกขั้นพร้อมแล้ว" ชวนเผยแพร่, แก้ข้อมูลหลังจัดแล้วกลับมาบอกให้จัดใหม่
- หน้า "วิธีใช้": ลองใช้ใน 5 นาที, ใช้งาน 10 ขั้นพร้อมภาพประกอบ (เปิดลิงก์ → เลือกวิธีเข้า → ตั้งคาบ → ข้อมูล → กรณีพิเศษ → กำหนดการเรียน(รวมวิชาเสรี) → จัดตาราง → เผยแพร่ → แจกไฟล์ → คู่มือเพิ่มเติม), คู่มือฉบับเต็ม 12 หัวข้อมีสารบัญ/กางทั้งหมด (รวมตารางแก้ปัญหา), คำศัพท์, ถามตอบ 10 ข้อ, ลิงก์คู่มือ PDF; ข้อความทั้งหมดเก็บไฟล์เดียว (help/content.ts) รองรับ **ตัวหนา** และ `ชื่อปุ่ม`
- ท้ายหน้า: เวอร์ชัน, MIT, ลิงก์คู่มือ PDF 2 ฉบับ

## 5) ระบบสิทธิ์และเผยแพร่ (ไม่มีเซิร์ฟเวอร์) — แยกมุมมอง นักเรียน / ครู / ผู้ดูแล
- หน้าเข้าสู่ระบบ: ช่องรหัส, ปุ่ม "ใช้งานเป็นผู้ดูแล (จัดตารางเอง)", ลิงก์ "มีไฟล์ตารางที่ได้รับ (published.enc.json)? เลือกไฟล์" (**ช่องเลือกไฟล์ห้ามกรองนามสกุล** เพราะไฟล์จากไลน์บนมือถือ; ตรวจจากเนื้อหาไฟล์ แจ้ง error อ่านรู้เรื่อง), ส่วนพับได้ "วิธีดูตาราง 3 ขั้น / ได้รับไฟล์ทางไลน์? (แยก Android/iPhone) / รหัสไม่ถูกต้อง"
- เผยแพร่: ผู้ดูแลตั้งชื่อชุดตาราง + **รหัสนักเรียน** + **รหัสครู** (ต่างกัน; ปุ่ม "สร้างรหัสให้" สุ่มรหัส 12 ตัว A–Z และ 2–9 รูปแบบ XXXX-XXXX-XXXX; ตัวตรวจความแข็งแรง) → สร้างไฟล์ `published.enc.json`: ซองเข้ารหัส 2 ซอง (นักเรียน/ครู) ใช้ PBKDF2-SHA256 600,000 รอบ + salt สุ่ม 16 ไบต์ → AES-256-GCM (IV 12 ไบต์) + gzip ก่อนเข้ารหัส; เนื้อในซองมีเฉพาะ "ตารางสำเร็จรูป" (นักเรียน = ตารางรายกลุ่ม, ครู = ตารางรายครู) ไม่มีข้อมูลดิบ; ทดสอบถอดรหัสก่อนให้ดาวน์โหลด; บทบาทมาจาก "ซองที่ถอดสำเร็จ" (ปลอมสิทธิ์ไม่ได้, พิมพ์ #/input เองก็ยังเป็นมุมมองผู้ดู); หน่วงเล็กน้อยเมื่อใส่รหัสผิดซ้ำ; จำกัดเพดาน iter/ขนาดกันไฟล์ปลอม
- แจกไฟล์ 2 ทาง: (A) วางที่ public/published/ บนเว็บ (ผู้ดูแค่เปิดลิงก์+ใส่รหัส) (B) ส่งไฟล์ทางไลน์/อีเมล แล้วผู้ดูเลือกไฟล์; มีปุ่มคัดลอก "ข้อความแจ้งผู้ดู" แยกนักเรียน/ครู (ลิงก์+รหัส)
- มุมมองผู้ดู: ตารางอ่านอย่างเดียว เลือกกลุ่ม/ครู, Export PDF/Excel, ปุ่มออกจากระบบ; ไม่มีเมนู/route แก้ไข
- รหัสล็อกผู้ดูแล (เฉพาะเครื่องนี้): แค่ล็อกหน้าจอ เก็บเฉพาะแฮช (localStorage `tt-admin-lock`) ลืมรหัสต้องรีเซ็ตเครื่อง (ลบข้อมูล) พร้อมคำอธิบายตรงๆ ว่าไม่ได้เข้ารหัสข้อมูล; session เก็บใน sessionStorage `tt-session`
- ข้อจำกัดที่ต้องบอกผู้ใช้ตรงๆ ในหน้า: รหัสเป็นรหัสร่วมของกลุ่ม ยกเลิกรายคนไม่ได้ ถ้าหลุดต้องตั้งใหม่และเผยแพร่ใหม่; ระบบไม่เก็บรหัส ลืมกู้คืนไม่ได้
