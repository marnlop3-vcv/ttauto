# คู่มือทำความเข้าใจโค้ด — ระบบจัดตารางสอนอัตโนมัติ (v1.8.0)

เอกสารนี้เขียนให้คน **ที่ไม่ใช่โปรแกรมเมอร์** อ่านแล้วรู้ว่า "โค้ดอยู่ที่ไหน ทำอะไร และถ้าอยากแก้ต้องไปที่ไหน" ไม่ต้องเข้าใจภาษาโปรแกรมก็อ่านได้ ถ้าเจอศัพท์แปลกๆ ให้ดูหัวข้อ "คำศัพท์" ท้ายเล่ม

โค้ดทั้งหมดอยู่ที่ https://github.com/marnlop3-vcv/ttauto (และในไฟล์ ZIP ที่แนบมา)

---

## 1. ภาพรวมในหนึ่งนาที

- โปรแกรมนี้เป็น **เว็บแอป** เปิดในเบราว์เซอร์ (Chrome/Edge/Safari) **ไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูลกลาง** ทุกอย่างทำงานและเก็บข้อมูลในเครื่องของผู้ใช้เอง
- เขียนด้วย **TypeScript** (ภาษา JavaScript ที่เพิ่มการตรวจชนิดข้อมูล) ใช้ **React** วาดหน้าจอ และ **Vite** เป็นเครื่องมือประกอบโค้ดให้เป็นเว็บ
- หัวใจของโปรแกรมคือไฟล์ **`src/lib/scheduler.ts`** (ตัวจัดตาราง) ส่วนอื่นเป็นหน้าจอ การนำเข้า/ส่งออก ระบบรหัส และเอกสาร
- เมื่อแก้โค้ดแล้ว push ขึ้น GitHub ระบบ (GitHub Actions) จะ build และเผยแพร่เป็นเว็บให้เองอัตโนมัติ

ลองเปรียบเทียบเป็นร้านอาหาร:

| ส่วนของร้าน | ในโปรแกรม |
|---|---|
| หน้าร้าน/เมนู/โต๊ะ (สิ่งที่ลูกค้าเห็น) | `pages/` และ `components/` (หน้าจอ) |
| สมุดจดออเดอร์ | `store.ts` (ที่เก็บข้อมูลที่ผู้ใช้กรอก) |
| พ่อครัว | `lib/scheduler.ts` (ตัวจัดตาราง) ทำงานในครัวหลังร้านคือ Web Worker |
| ใบสั่งซื้อวัตถุดิบ/ใบเสร็จ | `lib/excel.ts`, `pdf.ts` (นำเข้า/ส่งออกไฟล์) |
| ตู้เซฟและกุญแจ | `auth/` (เข้ารหัสและรหัสผ่าน) |
| ป้ายบอกวิธีใช้ | `help/content.ts` (ข้อความคู่มือ) |

## 2. แผนที่โฟลเดอร์

```
timetable-app/
├─ index.html            ← หน้าเว็บเปล่าที่โปรแกรมจะมาแปะตัวเอง
├─ package.json          ← รายชื่อแพ็กเกจที่ใช้ + คำสั่งลัด (npm run ...) + เวอร์ชัน
├─ vite.config.ts        ← ตั้งค่าเครื่องมือ build (base './' ทำให้ใช้ในโฟลเดอร์ย่อยได้)
├─ tsconfig.json         ← ตั้งค่าตัวตรวจชนิดข้อมูลของ TypeScript
├─ src/                  ← ★ โค้ดโปรแกรมทั้งหมด (ดูหัวข้อ 4)
├─ tests/                ← ชุดทดสอบอัตโนมัติ (ดูหัวข้อ 7)
├─ scripts/              ← สคริปต์ช่วยงาน: ทดสอบผ่านหน้าเว็บ, ถ่ายภาพหน้าจอ, สร้างคู่มือ PDF
├─ public/               ← ไฟล์ที่ถูกคัดลอกขึ้นเว็บตรงๆ: ไอคอน, คู่มือ PDF, ภาพประกอบหน้า "วิธีใช้"
├─ sample-data/          ← ไฟล์ตัวอย่าง (Excel/CSV/JSON) ขนาดเล็ก/กลาง/ใหญ่ ไว้ลอง Import
├─ docs/                 ← เอกสาร: คู่มือ, สไลด์, รายงาน, คู่มือโค้ดนี้ (ไม่ถูกเผยแพร่บนเว็บ)
├─ .github/workflows/    ← deploy.yml = ขั้นตอน build/ทดสอบ/เผยแพร่อัตโนมัติ
├─ README.md             ← สรุปโปรเจกต์ + ประวัติแต่ละเวอร์ชัน
└─ LICENSE, THIRD_PARTY_NOTICES.md   ← สัญญาอนุญาต MIT และรายชื่อแพ็กเกจของคนอื่นที่ใช้
```

> โฟลเดอร์ `node_modules/` (แพ็กเกจที่ติดตั้ง) และ `dist/` (เว็บที่ build เสร็จ) **ไม่ต้องเก็บ** สร้างใหม่ได้เสมอ จึงไม่อยู่ใน ZIP/GitHub

## 4. ไฟล์ในโฟลเดอร์ `src/` ทีละส่วน

### 4.1 ข้อมูลพื้นฐาน

| ไฟล์ | หน้าที่ (พูดแบบง่าย) | สิ่งสำคัญที่ควรรู้ |
|---|---|---|
| `types.ts` | **พจนานุกรมข้อมูล** บอกว่าข้อมูลแต่ละอย่างมีหน้าตาอย่างไร: ครู กลุ่มเรียน วิชา อาคาร กรณีพิเศษ **กำหนดการเรียน (Assignment)** การตั้งค่าคาบ และผลตาราง (Schedule) | `Assignment` มี `room` (ห้องหลัก) และ `extraRooms` (ห้องเพิ่มสำหรับวิชาเสรี); ฟังก์ชัน `roomsOf()` รวมห้องทั้งหมดให้ |
| `store.ts` | **สมุดจดข้อมูล** เก็บข้อมูลที่ผู้ใช้กรอกทั้งหมด และบันทึกลงเบราว์เซอร์เองอัตโนมัติ (คีย์ `timetable-app-v1`) | มีฟังก์ชันเพิ่ม/ลบข้อมูล; ลบอาคารแล้วจะจัดการกำหนดการเรียนที่เกี่ยวข้องให้; `stale` = ข้อมูลเปลี่ยนหลังจัดตาราง |
| `lib/entities.ts` | **กฎตรวจแถวข้อมูล** ของแต่ละชนิด (ครู กลุ่ม วิชา อาคาร กรณีพิเศษ) ใช้ทั้งในฟอร์มกรอกและตอน Import | ถ้าจะเปลี่ยนหัวคอลัมน์ใน Template หรือข้อความแจ้งผิด ให้แก้ที่นี่ |
| `lib/sample.ts` | สร้าง **ข้อมูลตัวอย่าง** 3 ขนาด (เล็ก 4 กลุ่ม / กลาง 12 / ใหญ่ 30) | ปุ่ม "ลองใช้ด้วยข้อมูลตัวอย่าง" เรียกที่นี่ |

### 4.2 ตัวจัดตาราง (หัวใจ)

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/scheduler.ts` (≈700 บรรทัด) | **ตัวจัดตาราง** คลาส `SchedulerEngine` ดูรายละเอียดภายในที่หัวข้อ 5 |
| `lib/scheduler.worker.ts` | **ห้องครัวหลังร้าน (Web Worker)** รับข้อมูลมาให้ตัวจัดตารางทำงานแยกจากหน้าจอ ส่งความคืบหน้ากลับทุกๆ ประมาณ 80 มิลลิวินาที รับคำสั่ง "หยุด" ได้ |
| `lib/schedulerClient.ts` | **พนักงานเสิร์ฟ** ฟังก์ชัน `runScheduler()` ที่หน้าจอเรียกใช้ สร้าง Worker ส่งงาน รับผล (ถ้า Worker เปิดไม่ได้ จะทำงานบนหน้าจอแบบแบ่งช่วงแทน) |
| `lib/thaiRuleParser.ts` | **ตัวแปลภาษาไทย** แปลงข้อความ เช่น "วันพุธ คาบ 7-8" หรือ "ทุกวัน ช่วงบ่าย" ให้เป็นรายการ (วัน, คาบ) ที่ตัวจัดตารางเข้าใจ |

## 5. ภายในตัวจัดตาราง (`scheduler.ts`) แบบเดินทีละส่วน

ไฟล์นี้เรียงตามลำดับการทำงานจริง (ค้นหาชื่อฟังก์ชันได้ในไฟล์):

| ลำดับ | ชื่อฟังก์ชัน/ส่วน | ทำอะไร |
|---|---|---|
| 0 | `WEIGHTS` (ต้นไฟล์) | **น้ำหนักความไม่สวย** เช่น คาบว่างของนักเรียน 8, ของครู 2, ครูสอนติดเกิน 4 คาบ 3 ฯลฯ ปรับความสำคัญของ "ความสวย" ที่นี่ |
| 1 | `build()` | **เตรียมข้อมูล** แปลงกรณีพิเศษเป็นช่องที่ถูกล็อก, รวม/แยกกำหนดการเรียน (เป็น Unit), แบ่งวิชาเป็นช่วงติดกันช่วงละไม่เกิน 4 คาบ (เป็น Piece) |
| 2 | `construct()` + `greedyPlace()` | **ขั้น Greedy** เรียงชิ้นยากก่อน แล้ววางที่ที่เสียน้อยสุด |
| 3 | `repair()` | **ขั้นซ่อม (Ejection Chain + Tabu)** ชิ้นที่วางไม่ลงจะไล่ชิ้นที่ขวางออกเป็นทอดๆ และจดไว้ไม่ให้ไล่ซ้ำ |
| 4 | `anneal()`, `tryMove()`, `trySwap()` | **ขั้นขัดเกลา (Simulated Annealing)** สุ่มย้าย/เลื่อน/สลับ รับเมื่อดีขึ้นหรือแย่ลงเล็กน้อยตามอุณหภูมิ |
| 5 | `fits()`, `blockersAt()` | **ตัวตรวจ "ชนไหม"** ทุกการวาง/ขยับต้องผ่านตัวนี้ก่อนเสมอ จึงไม่มีการชน |
| 6 | `dayCost()`, `unitCost()`, `local()`, `totalCost()` | **ตัวคิดคะแนนความไม่สวย** (คำนวณเฉพาะส่วนที่เปลี่ยน จึงเร็ว) |
| 7 | `noteBest()`, `restoreBest()` | **จำตารางที่ดีที่สุดไว้** ตอนจบคืนแบบที่ดีที่สุด |
| 8 | `step()`, `finish()` | **ควบคุมการรัน** ลดอุณหภูมิตามเวลา, ตัดสินใจเวลาจบ (ครบเวลา หรือไม่ดีขึ้นแล้ว), แยกช่วงสำรอง `splitFallback()` |
| 9 | `result()` | **สรุปผล** รายการคาบที่วางได้ สาเหตุที่วางไม่ลง คำเตือน ตัวชี้วัดก่อน/หลังปรับ |
| — | `generateSchedule()` (ท้ายไฟล์) | ทางลัดสำหรับเรียกแบบรอผล ใช้ในการทดสอบ |

**ศัพท์ในโค้ด:** *Unit (หน่วยงาน)* = กลุ่มที่ต้องว่างพร้อมกัน, *Piece (ชิ้นงาน)* = สิ่งที่วางลงตารางหนึ่งครั้ง (ช่วงติดกัน 1–4 คาบ), *resource (ทรัพยากร)* = ครู/กลุ่มเรียน/ห้อง

## 6. ไล่ดูเส้นทาง: "เมื่อกดจัดตาราง เกิดอะไรขึ้น"

1. `pages/Dashboard.tsx` → ฟังก์ชัน `run()` เก็บข้อมูลจาก `store.ts`
2. เรียก `runScheduler()` ใน `lib/schedulerClient.ts` → สร้าง Web Worker จาก `scheduler.worker.ts`
3. Worker สร้าง `new SchedulerEngine(...)` → ในตัวสร้างเรียก `build()` แล้ว `construct()` (Greedy + ซ่อม)
4. วนเรียก `step()` ซ้ำๆ (Annealing) พร้อมส่งความคืบหน้ากลับให้หน้าจอวาดแถบ %
5. จบแล้ว `result()` ส่งผลกลับ → `Dashboard` เก็บด้วย `setSchedule()` ใน `store.ts` (บันทึกลงเบราว์เซอร์)
6. `views.ts` → `buildGrid()` สร้างตาราง → `TimetableGrid.tsx` วาดบนจอ

**ส่วนอื่นที่ควรรู้**
- *นำเข้า Excel:* `ExcelButtons.tsx` → `excel.ts` (`analyzeImport`) → `tabular.ts` อ่านไฟล์ → `entities.ts` ตรวจทีละแถว → `store.ts` เพิ่มข้อมูล
- *เผยแพร่:* `Publish.tsx` → `bundle.ts` (`buildPublished`: สร้างตารางสำเร็จรูปด้วย `views.ts` แล้วเข้ารหัสด้วย `crypto.ts` 2 ซอง) → ดาวน์โหลด `published.enc.json`
- *นักเรียน/ครูเข้าดู:* `Login.tsx` → โหลดไฟล์ (`fetchPublished` จากเว็บ หรือ `readPublishedFromFile` จากไฟล์ที่เลือก) → `openPublished` ลองไขทีละซอง → `session.ts` จำบทบาท → `App.tsx` แสดง `Viewer.tsx`

## 9. คำสั่งที่ใช้บ่อย (ต้องติดตั้ง Node.js ก่อน)

```bash
npm install          # ติดตั้งแพ็กเกจ (ทำครั้งแรกครั้งเดียว)

npm run build        # สร้างเว็บสำเร็จรูปในโฟลเดอร์ dist
```

## 10. คำศัพท์

| คำ | ความหมายแบบง่าย |
|---|---|
| **TypeScript** | ภาษาโปรแกรมที่เป็น JavaScript แต่ตรวจชนิดข้อมูลก่อนรัน ช่วยจับข้อผิดพลาด |
| **React / Component** | เครื่องมือวาดหน้าจอ; component = ชิ้นส่วนหน้าจอที่ใช้ซ้ำได้ เช่น ปุ่ม ตาราง |
| **Vite** | เครื่องมือประกอบโค้ดหลายไฟล์ให้เป็นเว็บหนึ่งชุด |
| **Store (Zustand)** | ที่เก็บข้อมูลกลางของโปรแกรม ทุกหน้าจออ่าน/เขียนจากที่เดียวกัน |
| **localStorage** | พื้นที่เก็บข้อมูลในเบราว์เซอร์ของเครื่องนั้น (ล้างเบราว์เซอร์ = หาย จึงมีปุ่มสำรองข้อมูล) |
| **Web Worker** | งานที่รันเบื้องหลัง แยกจากหน้าจอ ทำให้หน้าเว็บไม่ค้างตอนคำนวณหนัก |
| **Build** | ขั้นตอนประกอบโค้ดเป็นเว็บสำเร็จรูป |
| **Deploy** | การนำเว็บสำเร็จรูปขึ้นให้คนทั่วไปเข้าดูได้ (ที่นี่คือ GitHub Pages) |
| **GitHub Actions** | หุ่นยนต์ของ GitHub ที่รันขั้นตอน build/ทดสอบ/deploy ให้อัตโนมัติ |
| **Test (ทดสอบอัตโนมัติ)** | โค้ดที่เขียนไว้ตรวจว่าโปรแกรมทำงานถูก รันซ้ำได้ทุกครั้งที่แก้ |
| **E2E** | ทดสอบทั้งระบบโดยให้เบราว์เซอร์จำลองคลิกแบบผู้ใช้จริง |
| **Heuristic** | วิธีหาคำตอบที่ดีมากอย่างรวดเร็ว แต่ไม่รับประกันว่าดีที่สุดเสมอไป |
| **PBKDF2 / AES-GCM** | วิธีมาตรฐานสร้างกุญแจจากรหัสผ่าน และเข้ารหัสข้อมูลให้ตรวจได้ว่าไม่ถูกแก้ |
